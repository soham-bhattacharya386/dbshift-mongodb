DOCUMENTATION
How DBShift works
A guided look at the workflow inspired by the research paper.
01 — Create a project
Start a project and select the source database. Project records are stored in your MongoDB database.
02 — Upload a schema and logs
Upload a SQL file containing CREATE TABLE statements. Optionally add a query log with SELECT, INSERT, UPDATE and DELETE statements.
03 — Review schema analysis
DBShift extracts table names, columns and basic foreign-key relationships. A simplified query-count heuristic proposes embedding or referencing. The research paper uses a more sophisticated row-weighted access model and evaluation queue.
04 — Preview and save
Explore illustrative JSON documents, download them, and save them to your MongoDB project record. This does not transfer live source database records into production MongoDB collections.
Research basis: “Development of Migration Tool From Relational Database to Document-Oriented NoSQL Database Utilizing Relational Database Logs” (ICISS 2025). The implementation here is a teaching prototype, not a reproduction of the full published algorithm.
